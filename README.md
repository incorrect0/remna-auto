# Remna Auto 1.3.0

Собственный установщик RemnaNode + Caddy Selfsteal для Debian/Ubuntu с systemd.
Написан с нуля; исходный код RemnaSetup не включён. Python 3.10+, стандартная библиотека.

## Быстрый запуск

Репозиторий: https://github.com/incorrect0/remna-auto

Запуск на сервере **от root** одной командой:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/incorrect0/remna-auto/main/install.sh)
```

Загрузчик скачивает единый снимок репозитория, проверяет SHA256SUMS и запускает мастер.
Существующая установка не удаляется. Для просмотра плана добавьте `plan` в конец команды.
Временная папка удаляется после завершения; ввод с терминала сохраняется.

Из локальной копии/клона:

```bash
sudo bash install.sh
```

Мастер запросит HTTPS-адрес панели, домен Caddy, API-ключ и выбор профиля.
IPv4 и страна определяются автоматически. Имя ноды — английское название страны:
Germany, Germany 1, Germany 2. Если страна неизвестна: XX и auto-install 1, auto-install 2.
Геолокация IPv4 запрашивается по HTTPS у ipwho.is, резерв — ipapi.co (передаётся только публичный IPv4,
API-ключ панели туда не отправляется). На сервис — максимум 3 секунды, общий бюджет — 6 секунд.
Запросы выполняются в отдельных процессах с принудительным завершением по тайм-ауту,
включая зависший DNS и медленную передачу ответа. При недоступности обоих используется XX / auto-install.
Порт управления всегда 3001. Вопроса об отдельном reverse proxy ключе нет;
для таких панелей по-прежнему можно задать REMNA_PROXY_KEY в окружении.
Все inbound’ы выбираются автоматически, кроме конфликтующих с 22/80/443/3001,
другими выбранными inbound’ами или чужими слушающими службами. Причины пропуска выводятся.
Некорректные настройки REALITY и ошибки API не скрываются. Если подходящих inbound’ов
не осталось, установка останавливается до изменений.
В неинтерактивном режиме непустой inbound_uuids остаётся явным строгим выбором;
пустой включает автоматический выбор.

Потребуется API-токен Remnawave с правами чтения профилей/вычисленного конфига/нод/ключа
и создания, обновления, удаления нод (удаление нужно для отката собственной записи).
При отдельной защите панели через X-Api-Key используйте REMNA_PROXY_KEY.
Редиректы и отключение проверки TLS не используются.

## Схема портов

```text
Сайт / цель REALITY: домен:443 → Caddy → /var/www/site
Панель → IP ноды:3001 → RemnaNode API (доступ регулируется вашим firewall)
Клиенты VPN → порт из выбранного Xray inbound, например 8443 → REALITY → 127.0.0.1:443
```

3001 — порт управления RemnaNode, а не клиентский VPN-порт.
Caddy не может одновременно занимать 443 на том же IP, что и клиентский inbound Xray.
Поэтому неподходящий профиль останавливает установку до изменений.

Для использования именно локального Caddy в качестве Selfsteal в REALITY inbound должны быть:

```json
{
  "port": 8443,
  "streamSettings": {
    "security": "reality",
    "realitySettings": {
      "target": "127.0.0.1:443",
      "serverNames": ["node.example.com"],
      "xver": 0
    }
  }
}
```

Это только фрагмент: ключи REALITY, shortIds и прочие настройки должны уже быть
в профиле. Установщик читает и привязывает профиль, не редактируя общую конфигурацию
других нод. Hosts и внутренние сквады отдельно не создаются и не меняются.

## Caddyfile

```caddyfile
node.example.com:443 {
    root * /var/www/site
    try_files {path} /index.html
    file_server
}
```

Сайт доступен обычным браузерам. Caddy управляет публичным сертификатом и его
продлением. Для стандартной ACME-проверки нужен доступ извне к HTTP 80 и HTTPS 443.
Для получения сертификата A/AAAA должны указывать на эту машину; CDN-проксирование отключите.
Создать DNS-запись можно после установки: её отсутствие или несовпадение не отменяет установку RemnaNode.
Облачный firewall и уже существующие UFW/nftables могут дополнительно ограничивать
80/443, клиентские VPN-порты и 3001: установщик не сбрасывает чужие правила.

Установщик не создаёт правил firewall и не запрашивает исходящие IP панели.
Доступ к TCP 3001 со стороны панели обеспечьте самостоятельно. При обновлении старой
установки удаляется только собственная таблица remna_auto и её служба.

Внешний REALITY target/dest допустим: выводится предупреждение, профиль остаётся без изменений.
В этом случае Caddy обслуживает сайт отдельно и не является целью данного inbound.
Локальный target требует совпадающего serverNames и xver: 0. Inbound на 443 конфликтует с Caddy.

## План без установки

```bash
python3 setup.py plan
```

Этот режим читает API, предлагает профиль и показывает итоговые параметры;
не изменяет сервер, профиль и записи панели. Python уже должен быть установлен.

## Запуск без вопросов

Скопируйте config.example.json в config.json и заполните параметры и UUID профиля.
Пустой inbound_uuids означает все inbound’ы выбранного профиля.
API-ключ сохраните отдельным файлом с правами 600 вне раздаваемой папки сайта:

```bash
chmod 600 /root/remna-api.key
sudo bash install.sh install --config config.json --api-key-file /root/remna-api.key --non-interactive
```

Ключ можно вместо файла передать через переменную окружения REMNA_API_KEY,
отдельный ключ reverse proxy — REMNA_PROXY_KEY. Секреты аргументом командной строки
не принимаются и в state.json не записываются. Файл API-ключа, созданный оператором,
остаётся под его контролем. SECRET_KEY ноды хранится в /opt/remnanode/.env с правами 600.

## Повторный запуск, обновление, статус

Повторный запуск использует сохранённый UUID ноды, обновляет собственную запись,
не создаёт дубликат. При потере ответа POST установщик сверяет operation ID через API.
Чужой контейнер remnanode, занятый порт, чужой сайт или Caddyfile не перезаписываются.
Для изменения профиля используйте JSON с новым profile_uuid и inbound_uuids.

Docker-образ при первой установке разрешается в digest. Повторный запуск сохраняет
тот же образ. Обновление запрашивается явно:

```bash
sudo bash install.sh install --refresh-image
sudo bash install.sh status
```

Проверка статуса с REMNA_API_KEY дополнительно показывает isConnected из панели.

## Откат и данные

Перед изменениями создаётся /var/backups/remna-auto/ДАТА-ID/rollback.json с правами 600.
Он содержит прежние конфигурации, включая прежний SECRET_KEY при повторной установке.
Не публикуйте резервные копии. При ошибке производится автоматический откат локальных
файлов и собственной записи панели. Если API недоступен и откат API не удался, об этом
будет отдельное сообщение — журнал сохраняется для ручного восстановления.

```bash
sudo bash install.sh rollback --backup /var/backups/remna-auto/ДАТА-ID
```

Пакеты Docker/Caddy и загруженные образы после отката не удаляются.
Каталоги и журналы могут остаться; прежние файлы конфигурации восстанавливаются.
SSL-хранилище Caddy /var/lib/caddy сохраняется.
Логи контейнера ограничены 3×10 МБ; Xray-логи в /opt/remnanode/logs ротируются logrotate.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Проверяются валидация входных данных, конфликт портов, SNI/target/xver, выбор профиля,
payload создания ноды, повторный запуск, потеря ответа POST, принадлежность записи,
восстановление файлов и откат API, запрет redirect и маскирование секретов.
Живой ввод домена и выбранного профиля нужен для окончательной end-to-end проверки
публичного сертификата и соединения реальной ноды с панелью.

Сайт — самостоятельная адаптивная дизайн-концепция строительной компании «Линия».
Все иллюстрации, стили и шрифты локальные/встроенные; внешних трекеров и форм сбора данных нет.

Официальный API: https://docs.rw/api/
Официальные исходники: https://github.com/remnawave/backend и https://github.com/remnawave/node

## Публикация правок

Новые согласованные изменения публикуются коммитами в этом репозитории.
Ту же команду можно вызвать повторно для установки опубликованной версии скрипта.
Это не обновляет автоматически образ ноды: для этого нужен `--refresh-image`.
История изменений — CHANGELOG.md, порядок проверок — DEVELOPMENT.md.
Чтобы запустить конкретный опубликованный тег или коммит, задайте REMNA_AUTO_REF:

```bash
REMNA_AUTO_REF=v1.0.1 bash <(curl -fsSL https://raw.githubusercontent.com/incorrect0/remna-auto/main/install.sh)
```

Команда с тегом работает после создания соответствующего тега в GitHub.

## Оформление терминала

Баннер remna <3, цветные этапы и итоговая карточка работают без дополнительных пакетов.
В узком терминале используется компактный баннер. Цвет автоматически выключается
при перенаправлении вывода, TERM=dumb или наличии NO_COLOR.
Предпросмотр без установки и API-запросов: `python3 setup.py --preview`.

## Автоматическое включение BBR

Используется штатный модуль tcp_bbr текущего ядра, без сторонних скриптов,
замены ядра и перезагрузки. Устанавливаются procps/kmod, включаются
net.ipv4.tcp_congestion_control=bbr и net.core.default_qdisc=fq.
Настройки сохраняются в /etc/sysctl.d/99-remna-auto-bbr.conf; прежние значения
запоминаются для отката. Существующие qdisc интерфейсов принудительно не заменяются.
Если модуль недоступен или включение не удалось, выводится предупреждение.
BBR относится к TCP; ускорение любых соединений не гарантируется.
Режим plan не меняет sysctl, модули или файлы сервера.

## Центральный установщик по SSH

**Не рекомендуется размещать на сервере с панелью. Используйте отдельный управляющий сервер.**

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/incorrect0/remna-auto/main/install.sh) controller
remna-controller init
remna-controller deploy
```

При init один раз задаются HTTPS-адрес панели и API-ключ скрытым вводом.
Они хранятся только на управляющем сервере в /etc/remna-auto-controller/settings.json,
владелец root, каталог 700, файл 600. Шифрование диска/резервных копий остаётся
ответственностью администратора: root управляющего сервера может прочитать эти настройки.
Не открывается веб-порт и не создаётся внешний API управления.

Для новой ноды укажите SSH-доступ одной строкой: `IPv4` (root:22) или `user@IPv4:port`, пароль или путь
к приватному SSH-ключу на управляющем сервере, домен Caddy и профиль.
Пароль/фраза ключа вводятся скрыто и не сохраняются. SSH-ключ на ноду не копируется.
Нужен root или sudo без пароля. Для незнакомого сервера нужно сверить отпечаток;
изменившийся ключ отклоняется, known_hosts хранится локально с правами 600.

Панель вызывается управляющим сервером через SSH stdio-брокер. API-ключ и настоящий
адрес панели на ноду не отправляются; на ноде в служебном состоянии используется
https://panel.example.com. Там остаётся обязательный SECRET_KEY самой ноды с правами 600.
Повторную установку такой ноды выполняйте через контроллер; обычный установщик
потребует реальный адрес панели. Для отдельного X-Api-Key можно вручную добавить
proxy_key в защищённый settings.json. Не публикуйте этот файл и SSH-ключи.

Проверка без установки: `remna-controller deploy --plan` (передаёт временный worker
и делает только читающие запросы к панели). Временная папка на ноде удаляется при
нормальном завершении. После обрыва связи проверьте состояние удалённой установки
и локальный журнал отката на ноде: удалённая установка не является атомарной при
потере SSH. Автоматический откат сохраняется, пока SSH-соединение работает.
Контроллер не удаляет и не перезаписывает чужие службы.

## Меню запуска

При запуске install.sh без аргументов предлагаются два режима:
1. Центральный установщик (ноды по SSH).
2. Установка ноды на текущий сервер.
0 — выход без установки. В первом режиме после установки контроллера открывается его меню.
Для запуска без меню укажите `install` или `controller` явно; без терминала выбор режима обязателен.
Команды `plan`, `status`, `rollback`, `--preview` по-прежнему работают напрямую.

`remna-controller` без аргументов открывает цветное меню: установка ноды,
проверка плана, настройка панели или выход. Команды init/deploy остаются доступными.
Обновление оформления не удаляет сохранённые настройки панели и known_hosts.

## Установка до создания DNS

IPv4 берётся с сетевых интерфейсов сервера, затем из подходящей A-записи,
маршрута или внешних IPv4-сервисов api.ipify.org / ipv4.icanhazip.com.
У внешних запросов есть лимиты времени. Контроллер использует введённый SSH IPv4,
поэтому A-запись домена ему для адреса ноды не нужна.

Если DNS отсутствует/не совпадает, HTTPS-проверка откладывается, а RemnaNode
регистрируется и подключается к панели по IPv4. Caddy продолжает попытки выпуска
сертификата автоматически после появления DNS и доступа к 80/443.
Итоговая карточка показывает ожидание HTTPS; Selfsteal через этот Caddy заработает
после выпуска сертификата. Ошибка самого RemnaNode по-прежнему вызывает откат.

После установки или ошибки интерактивный запуск возвращается в главное меню.
Прямые команды без терминала завершаются с кодом результата, чтобы не ломать автоматизацию.

## Интерфейс и восстановление (1.3)

- Один стиль локального и SSH-интерфейса, перенос длинных строк и кириллицы,
  компактный заголовок в узком терминале. При перенаправлении, TERM=dumb и NO_COLOR
  цвет не выводится. `--preview` и `--version` не требуют root.
- Ошибка поля предлагает исправить только это поле. Единственный профиль выбирается
  автоматически; контроллер запоминает последний профиль в рамках текущей сессии.
- Незашифрованный SSH-ключ не требует лишнего ввода парольной фразы. Для защищённого
  ключа фраза запрашивается скрыто при необходимости; проверка отпечатка не отключается.
- SSH-пользователь и порт задаются одной строкой с IPv4, без двух отдельных вопросов.
- Повторный init позволяет оставить настройки панели нажатием Enter; адрес и ключ
  вводятся скрыто. Новые значения сохраняются только после проверки API.
- Во время длительных команд и удалённого запуска выводится статус каждые 10 секунд.
  У команд, подготовки пакетов, API и SSH-протокола есть тайм-ауты; вывод ошибок очищается
  от секретов и управляющих терминальных последовательностей.
- На повторном запуске сохранённый Docker digest используется без скачивания,
  если образ уже есть. Базовые зависимости не переустанавливаются без необходимости.
  Контроллер использует официальные HTTPS-репозитории отдельно от зеркал провайдера.
- Незавершённая установка оставляет указатель pending.json на защищённый журнал
  /var/backups/remna-auto. Следующий запуск предлагает восстановление с явным `yes`.
  Без подтверждения ничего не откатывается. Автоматизация должна сначала отдельно
  выполнить проверенный rollback; для неинтерактивного rollback требуется `--yes`.
- Изменение параметров существующей ноды подтверждается отдельно; `--yes` предназначен
  для явно запрошенного автоматического обновления. Удалённый контроллер также
  запрашивает подтверждение восстановления и обновления существующей ноды.

При обрыве SSH нельзя гарантировать завершение или откат удалённой операции.
Перед повтором проверьте статус и pending.json на целевом сервере. Конфигурации,
чужие службы и общие профили панели установщик не перезаписывает автоматически.

API выполняется в отдельном процессе: до 90 секунд на чтение с повторами и до 30 секунд
на изменение. Это ограничивает также DNS и медленные ответы. После потери ответа
создания ноды действует прежняя сверка по operation ID, без слепого повторного POST.
Ожидание сертификата ограничено 45 секундами; Caddy продолжает выпуск в фоне.
